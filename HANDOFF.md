# Handoff notes: how this project works

Written for anyone (a person, or a fresh Claude session with no memory of past
work) picking this project up. Read this, then `README.md` (how `config.js`
works), then `config.js` itself.

## What this is

"Written From The Hip" is a static comedy site plus a weekly email newsletter.
Live at **writtenfromthehip.com**. Two writers/characters: Teorge and Gomas.
The site is a 1996-style star field of "planets"; each planet is a page.

## Accounts and where things live

| Piece | Where | Notes |
|---|---|---|
| Code | GitHub `denbgc22-ops/written-from-the-hip` (SSH remote) | branch `main` |
| Hosting | Netlify, auto-deploys every push to `main` | **Always check the Netlify Deploys tab after pushing**; deploys occasionally fail to trigger silently |
| Domain / DNS | Netlify DNS | SPF, DKIM (`resend._domainkey`), DMARC and `send.` records are already set for Resend |
| Email sending | Resend (Broadcasts for newsletters; API for the welcome email) | Sender: `Teorge and Gomas <hello@writtenfromthehip.com>` |
| Subscribe form | `netlify/functions/subscribe.js` | Adds the contact to the Resend Audience and sends a plain-text welcome email |
| Secrets | Netlify env vars `RESEND_API_KEY`, `RESEND_AUDIENCE_ID` | Never commit these |
| Live "Stream Of Consciousness" | Firebase Realtime DB (`assets/stream.js`) | The Firebase web key in that file is public by design; write access is controlled by Firebase security rules and the owner's Firebase login. `netlify.toml` tells Netlify's secret scanner to skip that file |

No build step. Edit files, commit, push, Netlify publishes.

## Site structure

- `config.js` is the single source of content: every planet's name, position,
  page text, photos and links. `assets/app.js` renders pages from it and
  `assets/planets.js` draws the planets.
- Optional per-planet page features (all in `assets/app.js`): `streamPost`
  (single or array, optional `note`), `orb` with `icon`, `sidePhotos`
  (`{photo, href, hoverLabel, glow}`) with `sidePhotosGap` / `sidePhotosOverlap`,
  `blurbMaxWidth`, `subBlurb` (single or array), `centerPhoto` (`photos` array,
  `maxWidth`, `glow`), bookshelf `books` (`href` optional), `mapLinks`.
- `homeSubscribeLine` (home page, under the planets) holds the subscriber count
  text, e.g. `0,000,000,497`. It is a joke counter edited by hand.
- Images are in `assets/images/`. **Use hyphenated, lowercase file names** in
  `config.js` and newsletters (the originals with spaces are untracked
  leftovers and can be ignored/deleted).

## Weekly routine (new issue)

1. Get the week's section PDFs/images (opening, Fantasy Football Waiver Wire,
   Book Cover, Off The Dome essay, Fark, Venus, Public Dome-ain) and the
   issue title.
2. Copy images into `assets/images/` with hyphenated names.
3. Create `newsletter-N.html` by copying the latest issue and replacing each
   section (see `tools/build_newsletter_example.py`, which shows how Issue #6
   was generated by slicing the previous issue on its `<!-- ===== SECTION: ... -->`
   comment markers). Template is the *latest* issue, `newsletter-6.html`.
4. In `config.js`, **Latest Issue** planet: add the new issue as `blurb` /
   `blurbHref`, move the previous one to the top of `subBlurb`, and add it at the
   top of `mapLinks` (newest first).
5. Update the **Fark** planet (`subBlurb`, `centerPhoto`), **Book Coverz**
   (`books`), and **Public Dome-ain** (`streamPost` entries) when asked.
6. Commit and push; confirm the Netlify deploy; then send the issue.

## Sending a newsletter (Resend)

- Resend dashboard > Broadcasts > paste the HTML of `newsletter-N.html`.
- The footer must keep the exact link `{{{RESEND_UNSUBSCRIBE_URL}}}`, or Resend
  blocks the send ("No unsubscribe link detected").
- Images in the email are **absolute URLs** (`https://writtenfromthehip.com/assets/images/...`),
  so push and let Netlify deploy *before* sending, or images will be broken.
- Send a test to yourself first. Resend only reports Delivered / Bounced /
  Complained; it cannot show whether a message landed in spam.

## Email HTML rules and known quirks

- Table-based layout, inline styles plus a `<style>` block, no external CSS.
- **Gmail iPhone dark mode** inverts any readable background/border/text color
  (boxes turn white with dark text). Only images are exempt. Several fixes were
  tried (image tiles, text-fill overrides, mid-tone text) and all were rejected
  as looking worse; the decision was to **keep the original design** and accept
  the white-box inversion. Don't retry unless asked.
- Issue #5 and #6 use light-yellow (`#fff6a8`) book text and light-blue
  (`#b8e2ff`) waiver-wire text.
